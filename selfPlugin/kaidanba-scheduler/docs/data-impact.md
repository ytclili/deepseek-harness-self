# 数据影响评估（已确认并实施）

不修改业务数据库或 Harness 核心数据库。插件独立 JSON 存储，schemaVersion=1；位置绑定当前 profile，目录权限 0700、文件 0600。凭据仍由企业工具和 IM 管理。

顶层包含 revision、tasks、runs 和完整性 checksum。Task 保存 UUID、名称/描述、kind/time（单次 YYYY-MM-DD HH:mm 或每日 HH:mm，北京时间）、platform、botId/targetId、目标显示名、enabled/status、revision、nextRunAt、lastOccurrence、创建与更新时间、手动请求去重摘要。Run 保存任务关联、occurrenceKey、不可变任务快照及摘要、各阶段时间、状态、脱敏 detail、消息摘要和商品数量。无完整商品响应、完整消息文本、客户平台路由或 API 凭据。

最多 200 条任务及创建去重保留项，最近 1000 条执行记录；每个任务最多 1000 次独立手动请求，清理执行记录不清理该任务的去重摘要。正式创建含稳定 creationId 与原请求摘要 creationDigest，重复请求返回原任务，不重复新建。删除后仍保留该标识并占容量，旧请求不得重新创建。只有不带创建标识的旧内部任务可在后续新建时清理；执行快照按记录容量保留。所有写入串行，临时文件写入、fsync、原子 rename、目录 fsync 成功后才更新内存；存储失败阻止后续执行。排他目录锁拒绝第二实例，异常残留锁需人工核对处理。不支持或损坏的状态拒绝启动，不静默重建。

商品网络查询和 IM 投递不占用存储队列。执行前快照和发送前意图必须成功落盘；发送回执不明确或回执写盘失败，不自动重试。删除保留记录，卸载保留状态。恢复备份必须使用 scripts/state-backup.mjs，在停止宿主后执行，未结束任务全部暂停，核对后手动启用。

IM 侧唯一新增写入：用户将已聊会话保存为任务时，创建正式投递目标；按平台/机器人/会话路由生成确定性 ID，并复用已有匹配目标。任务保存失败可能留下已创建目标，不自动删除；不修改 IM 的凭据、会话内容或业务数据库。

后端测试全部使用临时文件和假工具/投递服务。没有通过真实客户发送验证结果，前端交互测试由用户承担。
